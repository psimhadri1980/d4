D4 · run/run.sh cheat sheet

run/run.sh [<runtime>:]<component>:<command> [args] [-- passthrough] [--verbose|-v] [--yes|-y] [--json]

Runtimes

locala detached process on local Node 24 (pid + log in run/.run)
podmancontainer d4-<name> on the host network
(omitted)the component's default (ls marks it *); test defaults to local

Infra and the gateway run on podman only. A selection mixing them uses podman for those and says so; naming one alone with local: fails. Old loc/con are rejected with a hint.

Always in dependency order (stop: reverse). run/run.sh ls lists all with category, runtimes and port.

status columns

RUNTIMEpodman · local · - · red podman+local = conflict
STATErunning · stopped · exited · conflict · orphan (pid file, no process)
HEALTHlive check (≤ 30 s old reused): healthy · unhealthy
BUILDimage hash · (stale) = source changed · pinned · source (watch) · via ui-modules

Exit code ≠ 0 on conflict, orphan or unhealthy. Filter: service:status, api,web:status.

Where things live

host.confD4_SCHEME · D4_HOST · D4_PORT · D4_TLS_PORT · D4_BIND
component.yamlbeside each component: ports, health, env, provides, runtimes, hooks, test
run/env/*.envcommon · images · dev-secrets · local.env (yours) · prod.env
run/.run/logs/run.log, build.log, <name>.{image,package,podman,local,hooks}.log
run/.run/env/merged env per runtime/component (what processes read)
run/schema/component.schema.json (the contract)

Shell vars win: WEBHOOK_INTERVAL_MS=2000 run/run.sh local:worker:deploy. D4_PROFILE=prod = prod.env, no dev secrets.

When something fails

statusfirst: where it runs, health, conflicts
doctorPodman, Node 24, cgroups, ports, contract, old containers
… --verbosestream every subprocess's output
<name>:logsthe component's own output

Every failure prints the command, exit code, last 40 lines, log file and a hint. Build errors stop the run before anything is stopped.
