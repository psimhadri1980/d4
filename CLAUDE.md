# D4: notes for AI coding sessions

Read [`docs/DEVELOPER_GUIDE.md`](docs/DEVELOPER_GUIDE.md) before changing code. It holds the ground rules, repo map, request flows, recipes, test matrix, error contract and known pitfalls.

Essentials:
- **One entry point:** `run/run.sh [<runtime>:]<component>:<command> [args]` (D78). Runtimes `local` (Node 24) and `podman`; components by name (`api`, `web-plan`, `postgres`), category (`ui`, `service`, `infra`, `tool`), group (`observability`), `stack` or a list (`api,worker`); commands `build`, `deploy`, `start`, `stop`, `reset`, `status`, `logs`, `test`, `exec`, `shell`. `run/run.sh help`, `ls`, `status`, `doctor`. Never call `podman run`/`build` for D4 components by hand, and never add compose files.
- **Components carry their own config:** each has a `component.yaml` beside it (`apps/<name>/`, `packages/cli/`, `infra/<name>/`), checked against `run/schema/component.schema.json` on every run. Put component-specific settings, ports, health checks, mounts and test mappings there; only shared settings go in `run/env/*.env`, the browser-facing origin only in `host.conf`. A new component needs a port of its own (checked for clashes).
- **Host network, no names:** every container runs with `--network host` and every component listens on `127.0.0.1:<port>`, the same on both runtimes. No Podman networks, no service names, no `host.containers.internal`, no `localhost` inside containers: dial `127.0.0.1:<port>` (tenant graphs go through `NEO4J_HOSTS`). The target environments allow none of these.
- **Gateway:** always a Podman container, the only browser-facing port, one origin from `host.conf` (default http://localhost:5173): web `/`, API `/api`, Keycloak `/auth`, modules `/mfe/<name>/`. No CORS, no other browser-facing ports. A component runs on one runtime at a time; `deploy`/`start` stop it on the other runtime first.
- **Fast loop:** `run/run.sh local:<app>:deploy` (hot reload behind the gateway), edit, `run/run.sh <app>:test` (unit tests of the packages changed since HEAD within the app), `<app>:test integration`, `<app>:test e2e` (only the specs mapped in its `component.yaml`). Builds compile once with the shared turbo cache; images rebuild only when their input hash changes.
- **Before committing:** test the touched apps on local Node first (above). Then `run/run.sh podman:<app>:deploy` for each touched app and rerun its e2e specs with `<app>:test e2e`. Run `stack:test static` when types, exports or dependencies change. `stack:test e2e` and `--all` runs are not required per commit. Commit one logical change at a time.
- **Dependencies:** after a `package.json` change, update `pnpm-lock.yaml` with `npx pnpm@<pinned> install` and commit it; `run.sh` installs with `--frozen-lockfile`.
- **Never let users send raw Cypher.** Catalog queries go through the checks in `packages/cypher`. Only `TenantGraphService` opens Neo4j connections.
- **Metamodel:** changes go in `packages/metamodel/starter.yaml` with a version bump. Never hard-code type lists.
- **Web:** a shell (`apps/web`) plus six lifecycle modules, each its own app (`apps/web-{explore,queries,plan,data,reporting,admin}`), loaded at run time through the module registry; the manifest and `lifecycleProblems()` in `@d4/web-platform` are the contract. In Podman the `ui-modules` image serves them; `local:web-<name>:deploy` serves one from source at the same path. A module imports only `@d4/web-platform`, `@d4/ui-kit`, `@d4/sdk` and domain packages (ESLint enforces it), and ships as a release (`run/run.sh web-<name>:exec -- publish <version>`) or in the module image. Call the API through the typed client in `@d4/web-platform`. Use `useId()` for field ids, an explicit empty option in list boxes, and theme tokens for colours.
- **Settings:** loaded through `@d4/config` from the merged file `run.sh` writes per component and runtime; no hard-coded URLs or secret defaults.
- **Diagnosing:** `run/run.sh status` first; every failure prints the command, its exit code and output tail; full logs are in `run/.run/logs/` (`--verbose` streams them).
- **Recording decisions:** add a row to the decision log in `docs/PLAN.md`.
